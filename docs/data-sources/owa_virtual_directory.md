# msexchangeserver_owa_virtual_directory (Data Source)

Reads an existing object by `name`, with the attributes of the [`msexchangeserver_owa_virtual_directory`](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/resources/owa_virtual_directory) resource. Use it to reference an object that this configuration does not manage, such as a default policy.

## Example Usage

```terraform
data "msexchangeserver_owa_virtual_directory" "ex01" {
  name = "EX01"
}

output "external_url" {
  description = "External URL of the virtual directory of EX01."
  value       = data.msexchangeserver_owa_virtual_directory.ex01.external_url
}
```

- `forms_authentication` (Boolean) Forms-based authentication.
- `id` (String) The object name (same as `name`).
- `internal_authentication_methods` (Set of String) Authentication methods Exchange advertises to clients inside the network.
- `internal_url` (String) URL used inside the network. An empty string clears it.
- `oauth_authentication` (Boolean) OAuth authentication.
- `windows_authentication` (Boolean) Integrated Windows authentication in IIS.

## Permissions

The provider's account needs `Get-OwaVirtualDirectory` and `Set-OwaVirtualDirectory`, from the **Exchange Virtual Directories** management role. The role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeserver/blob/main/tools/new_role_group.ps1) grants them through a custom role that holds only the `Get-` and `Set-` cmdlets of the virtual directories: the built-in role can also create and remove them. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/authentication).
