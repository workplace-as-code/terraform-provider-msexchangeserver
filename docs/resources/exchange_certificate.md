# msexchangeserver_exchange_certificate (Resource)

Imports a certificate with its private key (a PFX file) on an Exchange server, and removes it on destroy. The PFX and its password are write-only attributes: they are sent to Exchange when the certificate is created and are never stored in the plan or the state. Requires Terraform 1.11 or later. Enable the certificate for services with `msexchangeserver_exchange_certificate_services`.

## Example Usage

```terraform
variable "mail_pfx_password" {
  description = "Password of the PFX file. Ephemeral: never stored in a plan or the state."
  type        = string
  sensitive   = true
  ephemeral   = true
}

# The certificate of mail.contoso.com, imported from a PFX file on the
# machine that runs Terraform, then enabled for IIS and SMTP.
resource "msexchangeserver_exchange_certificate" "mail_2027" {
  server          = "EX01.contoso.com"
  thumbprint      = "0123456789ABCDEF0123456789ABCDEF01234567"
  pfx_base64_wo   = filebase64("${path.module}/mail-2027.pfx")
  pfx_password_wo = var.mail_pfx_password
  friendly_name   = "mail.contoso.com 2027"
}

resource "msexchangeserver_exchange_certificate_services" "mail_2027" {
  server     = msexchangeserver_exchange_certificate.mail_2027.server
  thumbprint = msexchangeserver_exchange_certificate.mail_2027.thumbprint
  services   = ["IIS", "SMTP"]
}
```

## Renewing a certificate

Declare the new certificate as a second resource and move the services to it, then remove the old certificate from the configuration once the new one serves them:

1. Add the new `msexchangeserver_exchange_certificate` and point the `msexchangeserver_exchange_certificate_services` resource at its thumbprint. Apply: Exchange enables the services on the new certificate.
2. Remove the old certificate from the configuration. Apply: the provider removes it from the server.

Changing `thumbprint` on a single certificate resource does not work: Terraform would remove the old certificate before it imports the new one, and the provider refuses to remove a certificate still enabled for IIS, POP or IMAP.

## Limitations

- Terraform 1.11 or later (write-only attributes). The PFX and its password are only read when the certificate is created.
- The persistent PowerShell bridge (the default): with `EXCHANGE_BRIDGE_MODE=oneshot`, the provider refuses to import a PFX, whose password would be on the PowerShell command line.
- Mailbox servers only. Each server has its own certificates: declare one resource per server.
- The import ID and the configuration must name the server the same way: a different `server` replaces the certificate. `terraform query` uses the FQDN.

## Schema

### Required

- `server` (String) The Exchange server that holds the certificate, as a name or an FQDN. Each server has its own certificates.
- `thumbprint` (String) The thumbprint of the certificate: 40 hexadecimal characters in upper case.

### Optional

> **NOTE**: [Write-only arguments](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments) are supported in Terraform 1.11 and later.

- `friendly_name` (String) The friendly name of the certificate on the server. Changing it replaces the certificate.
- `pfx_base64_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The PFX file, encoded in base64 (for example `filebase64("mail.pfx")`, or an ephemeral value from a secret store). Required to create the certificate: the provider checks that the PFX holds the certificate of `thumbprint` before importing it. Write-only: changing it does not replace the certificate; change `thumbprint` to import a new one.
- `pfx_password_wo` (String, Sensitive, [Write-only](https://developer.hashicorp.com/terraform/language/resources/ephemeral#write-only-arguments)) The password of the PFX file. Write-only.
- `private_key_exportable` (Boolean) Whether the private key can be exported from the server after the import. Exchange's default is `false`. Changing it replaces the certificate.

### Read-Only

- `certificate_domains` (List of String) The domains of the certificate: its subject and subject alternative names.
- `id` (String) The identity of the certificate, `<server>\<thumbprint>`.
- `issuer` (String) The issuer of the certificate.
- `not_after` (String) The end of the validity period, in UTC (RFC 3339).
- `not_before` (String) The start of the validity period, in UTC (RFC 3339).
- `self_signed` (Boolean) Whether the certificate is self-signed.
- `subject` (String) The subject of the certificate, for example `CN=mail.contoso.com`.

## Permissions

The provider's account needs `Get-`, `Import-` and `Remove-ExchangeCertificate`, from the **Exchange Server Certificates** management role. The role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeserver/blob/main/tools/new_role_group.ps1) grants them through a custom role without `Export-ExchangeCertificate`, which exports private keys. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/authentication).

## Import

Import using the certificate identity, `<server>\\<thumbprint>`. The certificate stays on the server: `pfx_base64_wo` is only needed to create it.

```terraform
import {
  to = msexchangeserver_exchange_certificate.mail_2027
  id = "EX01.contoso.com\\0123456789ABCDEF0123456789ABCDEF01234567"
}
```

Or by identity (Terraform 1.12 and later):

```terraform
import {
  to       = msexchangeserver_exchange_certificate.mail_2027
  identity = { id = "EX01.contoso.com\\0123456789ABCDEF0123456789ABCDEF01234567" }
}
```

Or with the CLI:

```shell
terraform import msexchangeserver_exchange_certificate.mail_2027 \
  "EX01.contoso.com\\0123456789ABCDEF0123456789ABCDEF01234567"
```

To import every existing object at once, see [Import an existing organization](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/import_existing).
