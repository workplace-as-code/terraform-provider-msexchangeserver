# msexchangeserver_web_services_virtual_directory (Resource)

Manages the URLs of the Exchange Web Services (EWS) virtual directory of an Exchange server (`Set-WebServicesVirtualDirectory`). The object cannot be created: the resource adopts the existing one. Only the attributes set in the configuration are managed; the others keep their current value. Destroying this resource removes it from Terraform state without changing Exchange. `name` is the server name or FQDN, for the virtual directory of the Default Web Site, or its identity as `Get-WebServicesVirtualDirectory` shows it, such as `EX01\EWS (Default Web Site)`. Authentication settings are not managed.

## Example Usage

```terraform
# The same namespace inside and outside the network.
resource "msexchangeserver_web_services_virtual_directory" "ex01" {
  name         = "EX01"
  internal_url = "https://mail.contoso.com/EWS/Exchange.asmx"
  external_url = "https://mail.contoso.com/EWS/Exchange.asmx"
}
```

## Schema

### Required

- `name` (String) The name. Changing it creates a new object.

### Optional

- `external_url` (String) URL used from the internet. An empty string clears it.
- `internal_url` (String) URL used inside the network. An empty string clears it.

### Read-Only

- `id` (String) The object name (same as `name`).

## Permissions

The provider's account needs `Get-WebServicesVirtualDirectory` and `Set-WebServicesVirtualDirectory`, from the **Exchange Virtual Directories** management role. The role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeserver/blob/main/tools/new_role_group.ps1) grants them through a custom role that holds only the `Get-` and `Set-` cmdlets of the virtual directories: the built-in role can also create and remove them. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/authentication).

## Import

Import using the server name:

```terraform
import {
  to = msexchangeserver_web_services_virtual_directory.ex01
  id = "EX01"
}
```

Or by identity (Terraform 1.12 and later):

```terraform
import {
  to       = msexchangeserver_web_services_virtual_directory.ex01
  identity = { id = "EX01" }
}
```

Or with the CLI:

```shell
terraform import msexchangeserver_web_services_virtual_directory.ex01 "EX01"
```

To import every existing object at once, see [Import an existing organization](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/import_existing).
