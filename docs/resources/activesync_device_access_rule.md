# msexchangeserver_activesync_device_access_rule (Resource)

Manages an Exchange ActiveSync device access rule (`New-ActiveSyncDeviceAccessRule`), which allows, blocks or quarantines the mobile devices that match a device type, model, operating system or user agent. Devices that match no rule get the default access level of `msexchangeserver_activesync_organization_settings`.

## Example Usage

```terraform
# iPhones are allowed, whatever the default access level.
resource "msexchangeserver_activesync_device_access_rule" "iphone" {
  query_string   = "iPhone"
  characteristic = "DeviceModel"
  access_level   = "Allow"
}
```

## Schema

### Required

- `access_level` (String) What happens to the matching devices. Valid values: `Allow`, `Block`, `Quarantine`.
- `characteristic` (String) Device property the rule matches. Valid values: `DeviceType`, `DeviceModel`, `DeviceOS`, `UserAgent`, `XMSWLHeader`. Changing it creates a new rule.
- `query_string` (String) Value the device property must equal, as Exchange reports it in `Get-MobileDevice`, for example `iPhone` or `iOS 17.5 21F79`. Wildcards and partial matches are not supported. Changing it creates a new rule.

### Read-Only

- `id` (String) Name Exchange gives the rule: `<query_string> (<characteristic>)`, for example `iPhone (DeviceModel)`.

## Permissions

The provider's account needs these cmdlets of the **Organization Client Access** management role. The role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeserver/blob/main/tools/new_role_group.ps1) grants them through a custom role that holds only the ActiveSync cmdlets: the built-in role can also change the protocols of each user and the organization configuration. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/authentication).
