# msexchangeserver_client_access_service (Resource)

Manages the Autodiscover settings of the Client Access services of an Exchange server: the URL that domain-joined Outlook clients find in Active Directory (`Set-ClientAccessService`). The object cannot be created: the resource adopts the existing one. Only the attributes set in the configuration are managed; the others keep their current value. Destroying this resource removes it from Terraform state without changing Exchange. `name` is the server name or FQDN.

## Example Usage

```terraform
# Domain-joined Outlook clients find Autodiscover through Active Directory.
locals {
  autodiscover_url = "https://autodiscover.contoso.com/Autodiscover/Autodiscover.xml"
}

resource "msexchangeserver_client_access_service" "ex01" {
  name                              = "EX01"
  autodiscover_service_internal_uri = local.autodiscover_url
}
```

### Optional

- `autodiscover_service_internal_uri` (String) Autodiscover URL published in Active Directory (service connection point), for example `https://autodiscover.contoso.com/Autodiscover/Autodiscover.xml`. An empty string clears it.

## Permissions

The provider's account needs `Get-ClientAccessService` and `Set-ClientAccessService`, from the **Exchange Servers** management role. The role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeserver/blob/main/tools/new_role_group.ps1) grants them through a custom role that holds only these cmdlets: the built-in role can also change every server setting. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/authentication).
