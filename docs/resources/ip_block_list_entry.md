# msexchangeserver_ip_block_list_entry (Resource)

Manages an entry of the IP block list of the connection filter agent: connections from the address or range are always rejected (`New-IPBlockListEntry`). Attributes left out of the configuration take the Exchange default when the object is created and are not managed afterwards. `name` is the IP address (`192.0.2.10`), CIDR range (`192.0.2.0/24`) or address range (`192.0.2.1-192.0.2.9`), as `Get-IPBlockListEntry` shows it. Any change creates a new entry. An Edge Transport setting: on a Mailbox server, it needs the anti-spam agents and the Transport Hygiene role.

## Example Usage

```terraform
# Block an address until the end of the year.
resource "msexchangeserver_ip_block_list_entry" "abuser" {
  name            = "198.51.100.7"
  comment         = "Spam campaign, ticket 4512"
  expiration_time = "2027-01-01T00:00:00Z"
}
```

## Schema

### Required

- `name` (String) The name. Changing it creates a new object.

### Optional

- `comment` (String) Free text about the entry.
- `expiration_time` (String) When the entry expires, in RFC 3339 format and UTC, for example `2027-01-31T00:00:00Z`. Empty never expires.

### Read-Only

- `id` (String) The object name (same as `name`).

## Permissions

On an Edge Transport server, the account is a local administrator: Exchange has no role-based access control there. On a Mailbox server with the anti-spam agents installed, it needs the **Transport Hygiene** management role, which the role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeserver/blob/main/tools/new_role_group.ps1) does not include. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/authentication).
