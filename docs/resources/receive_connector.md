# msexchangeserver_receive_connector (Resource)

Manages a receive connector of an Exchange server, which accepts SMTP connections on given addresses and ports from given IP ranges (`New-ReceiveConnector`). Attributes left out of the configuration take the Exchange default when the object is created and are not managed afterwards. `name` is the identity of the connector, `<server>\<name>`, with the server's short name, as `Get-ReceiveConnector` shows it: changing it creates a new connector on that server. `bindings` is required to create a connector, which is created with the `Custom` usage: set its `permission_groups` and `auth_mechanism`. For an application that relays mail, prefer `permission_groups = ["ExchangeServers"]` with `auth_mechanism = ["ExternalAuthoritative"]` on narrow `remote_ip_ranges`: it needs no Active Directory permission.

## Example Usage

```terraform
# Relay for two application servers, without Active Directory permissions:
# the connector treats them as Exchange servers (externally secured).
resource "msexchangeserver_receive_connector" "app_relay" {
  name              = "EX01\\Application relay"
  transport_role    = "FrontendTransport"
  bindings          = ["0.0.0.0:25"]
  remote_ip_ranges  = ["10.10.5.21", "10.10.5.22"]
  permission_groups = ["ExchangeServers"]
  auth_mechanism    = ["Tls", "ExternalAuthoritative"]
}
```

## Schema

### Required

- `name` (String) The name. Changing it creates a new object.

### Optional

- `auth_mechanism` (Set of String) Authentication offered: `None`, `Tls`, `Integrated`, `BasicAuth`, `BasicAuthRequireTLS`, `ExchangeServer`, `ExternalAuthoritative`.
- `banner` (String) SMTP banner, starting with `220`. Empty uses the Exchange default.
- `bindings` (Set of String) Local addresses and ports, as `0.0.0.0:25` or `[::]:25`.
- `comment` (String) Free text about the connector.
- `enabled` (Boolean) Whether the connector accepts connections.
- `fqdn` (String) Name the connector gives in its banner and EHLO response.
- `max_message_size_mb` (Number) Largest message, in megabytes, the connector accepts. `0` means unlimited.
- `permission_groups` (Set of String) Groups allowed to use the connector: `AnonymousUsers`, `ExchangeUsers`, `ExchangeServers`, `ExchangeLegacyServers`, `Partners`, `Custom`.
- `protocol_logging_level` (String) SMTP protocol logging. Valid values: `None`, `Verbose` (case-insensitive).
- `remote_ip_ranges` (Set of String) Remote IP addresses, ranges (`10.0.0.1-10.0.0.9`) or CIDR blocks the connector accepts.
- `require_tls` (Boolean) Require TLS for every connection.
- `tls_certificate_name` (String) Certificate the connector presents, as `<I>issuer<S>subject`.
- `transport_role` (String) Transport service of the connector on a Mailbox server. Valid values: `FrontendTransport`, `HubTransport` (case-insensitive).

### Read-Only

- `id` (String) The object name (same as `name`).

## Permissions

The provider's account needs the **Receive Connectors** management role, which the role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeserver/blob/main/tools/new_role_group.ps1) and the **Organization Management** role group include. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/authentication). On an Edge Transport server, the account is a local administrator.

## Import

Import using the connector identity, `<server>\\<name>`:

```terraform
import {
  to = msexchangeserver_receive_connector.app_relay
  id = "EX01\\Application relay"
}
```

Or by identity (Terraform 1.12 and later):

```terraform
import {
  to       = msexchangeserver_receive_connector.app_relay
  identity = { id = "EX01\\Application relay" }
}
```

Or with the CLI:

```shell
terraform import msexchangeserver_receive_connector.app_relay "EX01\\Application relay"
```
