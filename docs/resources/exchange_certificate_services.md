# msexchangeserver_exchange_certificate_services (Resource)

Enables an Exchange certificate for services (`Enable-ExchangeCertificate`): IIS (HTTPS), SMTP, IMAP and POP. Exchange cannot take a service away from a certificate: a service removed from `services`, or a destroy, leaves the certificate enabled for it. To move a service, enable it on the new certificate.

## Example Usage

```terraform
# A certificate already on the server (requested and completed in the
# Exchange admin center), enabled for HTTPS, SMTP, IMAP and POP.
resource "msexchangeserver_exchange_certificate_services" "mail" {
  server     = "EX01.contoso.com"
  thumbprint = "0123456789ABCDEF0123456789ABCDEF01234567"
  services   = ["IIS", "SMTP", "IMAP", "POP"]
}
```

## Limitations

- `SMTP` means the default SMTP certificate of the server, the internal transport certificate of `Get-TransportService`. `Get-ExchangeCertificate` also shows SMTP on other certificates, which Exchange marks on its own: the provider ignores that mark.
- Exchange only accepts a certificate whose private key is in a CryptoAPI provider (CSP) as the default SMTP certificate, because EdgeSync uses it: a CNG key fails with "isn't a Cryptographic API certificate". Certificates completed from an Exchange request are CSP; a PFX made with `New-SelfSignedCertificate` or other tools may hold a CNG key.
- Enabling SMTP replaces the default SMTP certificate without the confirmation that `Enable-ExchangeCertificate` asks for (`-Force`). Check what relies on the previous one first, such as the `tls_certificate_name` of connectors.
- Services that the certificate carries but `services` does not list are left as they are; an imported resource lists them all.
- Mailbox servers only.

## Schema

### Required

- `server` (String) The Exchange server that holds the certificate, as a name or an FQDN. Each server has its own certificates.
- `services` (Set of String) The services to enable the certificate for: `IIS`, `SMTP`, `IMAP`, `POP`. `SMTP` makes the certificate the default SMTP certificate of the server (the internal transport certificate), replacing the previous one without asking. Services that the certificate carries but that are not listed here are left as they are.
- `thumbprint` (String) The thumbprint of the certificate: 40 hexadecimal characters in upper case.

### Read-Only

- `id` (String) The identity of the certificate, `<server>\<thumbprint>`.

## Permissions

The provider's account needs `Get-ExchangeCertificate` and `Enable-ExchangeCertificate`, from the **Exchange Server Certificates** management role, and `Get-TransportService`, from the **Send Connectors** role. The role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeserver/blob/main/tools/new_role_group.ps1) grants them through a custom role without `Export-ExchangeCertificate`, which exports private keys. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/authentication).

## Import

Import using the certificate identity, `<server>\\<thumbprint>`. A certificate without services cannot be imported.

```terraform
import {
  to = msexchangeserver_exchange_certificate_services.mail
  id = "EX01.contoso.com\\0123456789ABCDEF0123456789ABCDEF01234567"
}
```

Or by identity (Terraform 1.12 and later):

```terraform
import {
  to       = msexchangeserver_exchange_certificate_services.mail
  identity = { id = "EX01.contoso.com\\0123456789ABCDEF0123456789ABCDEF01234567" }
}
```

Or with the CLI:

```shell
terraform import msexchangeserver_exchange_certificate_services.mail \
  "EX01.contoso.com\\0123456789ABCDEF0123456789ABCDEF01234567"
```

To import every existing object at once, see [Import an existing organization](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/import_existing).
