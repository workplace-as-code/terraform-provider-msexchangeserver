# msexchangeserver_content_filter_config (Resource)

Manages the content filter agent: what happens to a message according to its spam confidence level (SCL) (`Set-ContentFilterConfig`). This is a singleton: there is exactly one per organization. Only the attributes set in the configuration are managed; the others keep their current value. Destroying this resource removes it from Terraform state without changing Exchange. An Edge Transport setting: on a Mailbox server, it needs the anti-spam agents and the Transport Hygiene role.

## Example Usage

```terraform
# Reject at SCL 6 and above, quarantine nothing.
resource "msexchangeserver_content_filter_config" "this" {
  scl_reject_enabled   = true
  scl_reject_threshold = 6
}
```

## Schema

### Optional

- `bypassed_recipients` (Set of String) Recipients whose messages are never filtered.
- `bypassed_sender_domains` (Set of String) Sender domains whose messages are never filtered.
- `bypassed_senders` (Set of String) Senders whose messages are never filtered.
- `enabled` (Boolean) Whether the agent filters messages.
- `external_mail_enabled` (Boolean) Filter messages from outside the organization.
- `internal_mail_enabled` (Boolean) Filter messages from authenticated partners and internal servers.
- `quarantine_mailbox` (String) Address of the quarantine mailbox.
- `rejection_response` (String) Text of the rejection, up to 240 characters.
- `scl_delete_enabled` (Boolean) Delete the messages that reach `scl_delete_threshold`.
- `scl_delete_threshold` (Number) SCL from which messages are deleted.
- `scl_quarantine_enabled` (Boolean) Send the messages that reach `scl_quarantine_threshold` to the quarantine mailbox.
- `scl_quarantine_threshold` (Number) SCL from which messages are quarantined.
- `scl_reject_enabled` (Boolean) Reject the messages that reach `scl_reject_threshold`.
- `scl_reject_threshold` (Number) SCL from which messages are rejected.

### Read-Only

- `id` (String) Always `default`.

## Permissions

On an Edge Transport server, the account is a local administrator: Exchange has no role-based access control there. On a Mailbox server with the anti-spam agents installed, it needs the **Transport Hygiene** management role, which the role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeserver/blob/main/tools/new_role_group.ps1) does not include. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/authentication).

## Import

The resource is a singleton. Import it with the ID `default`:

```terraform
import {
  to = msexchangeserver_content_filter_config.this
  id = "default"
}
```

Or by identity (Terraform 1.12 and later):

```terraform
import {
  to       = msexchangeserver_content_filter_config.this
  identity = { id = "default" }
}
```

Or with the CLI:

```shell
terraform import msexchangeserver_content_filter_config.this "default"
```

To import every existing object at once, see [Import an existing organization](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/import_existing).
