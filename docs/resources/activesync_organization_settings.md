# msexchangeserver_activesync_organization_settings (Resource)

Manages the Exchange ActiveSync settings of the organization: what happens to mobile devices that match no device access rule (`Set-ActiveSyncOrganizationSettings`). This is a singleton: there is exactly one per organization. Only the attributes set in the configuration are managed; the others keep their current value. Destroying this resource removes it from Terraform state without changing Exchange.

## Example Usage

```terraform
# Unknown devices wait in quarantine until an administrator allows them.
resource "msexchangeserver_activesync_organization_settings" "this" {
  default_access_level  = "Quarantine"
  admin_mail_recipients = ["mobile-admins@contoso.com"]
  user_mail_insert      = "Your device is waiting for approval by the IT service desk."
}
```

## Schema

### Optional

- `admin_mail_recipients` (List of String) Email addresses notified when a device is quarantined.
- `allow_access_for_unsupported_platform` (Boolean) Let devices that do not support ActiveSync policies connect.
- `default_access_level` (String) Access of the devices that match no `msexchangeserver_activesync_device_access_rule`. Valid values: `Allow`, `Block`, `Quarantine` (case-insensitive).
- `ota_notification_mail_insert` (String) Text added to the message sent to users after they set up their mobile device.
- `user_mail_insert` (String) Text added to the message sent to users whose device is quarantined, up to 256 characters.

### Read-Only

- `id` (String) Always `default`.

## Permissions

The provider's account needs these cmdlets of the **Organization Client Access** management role. The role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeserver/blob/main/tools/new_role_group.ps1) grants them through a custom role that holds only the ActiveSync cmdlets: the built-in role can also change the protocols of each user and the organization configuration. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/authentication).

## Import

The resource is a singleton. Import it with the ID `default`:

```terraform
import {
  to = msexchangeserver_activesync_organization_settings.this
  id = "default"
}
```

Or by identity (Terraform 1.12 and later):

```terraform
import {
  to       = msexchangeserver_activesync_organization_settings.this
  identity = { id = "default" }
}
```

Or with the CLI:

```shell
terraform import msexchangeserver_activesync_organization_settings.this "default"
```

To import every existing object at once, see [Import an existing organization](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/import_existing).
