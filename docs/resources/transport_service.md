# msexchangeserver_transport_service (Resource)

Manages the log settings of the Transport service of an Exchange server: message tracking, connectivity and SMTP protocol logs (`Set-TransportService`). The object cannot be created: the resource adopts the existing one. Only the attributes set in the configuration are managed; the others keep their current value. Destroying this resource removes it from Terraform state without changing Exchange. `name` is the server name or FQDN. With the Mailbox role, `name` is a Mailbox server: manage an Edge Transport server with a provider whose role is Edge. SMTP protocol logging is turned on for each connector, with its `protocol_logging_level`. On a Mailbox server, the message tracking directory limit applies to the logs of the Transport service and to those of the Mailbox Transport service, each: they can take twice the size.

## Example Usage

```terraform
# Message tracking logs of EX01 kept 90 days on a dedicated disk.
resource "msexchangeserver_transport_service" "ex01" {
  name                                       = "EX01"
  message_tracking_log_path                  = "D:\\Logs\\MessageTracking"
  message_tracking_log_max_age_days          = 90
  message_tracking_log_max_directory_size_mb = 10240
  connectivity_log_max_age_days              = 90
  send_protocol_log_max_age_days             = 90
  receive_protocol_log_max_age_days          = 90
}
```

## Permissions

The provider's account needs `Get-TransportService` and `Set-TransportService`, and `Get-ExchangeServer`, from the **Exchange Servers** management role. The role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeserver/blob/main/tools/new_role_group.ps1) grants them through a custom role that holds only these cmdlets and those of the Front End Transport service: the built-in role can also change every server setting. Edge Transport servers have no role-based access control. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/authentication).

## Import

Import using the server name:

```terraform
import {
  to = msexchangeserver_transport_service.ex01
  id = "EX01"
}
```

Or by identity (Terraform 1.12 and later):

```terraform
import {
  to       = msexchangeserver_transport_service.ex01
  identity = { id = "EX01" }
}
```

Or with the CLI:

```shell
terraform import msexchangeserver_transport_service.ex01 "EX01"
```

To import every existing object at once, see [Import an existing organization](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/import_existing).
