# msexchangeserver_ip_block_list_providers_config (Resource)

Manages how the connection filter agent uses the IP block list providers (DNS block lists) (`Set-IPBlockListProvidersConfig`). This is a singleton: there is exactly one per organization. Only the attributes set in the configuration are managed; the others keep their current value. Destroying this resource removes it from Terraform state without changing Exchange. An Edge Transport setting: on a Mailbox server, it needs the anti-spam agents and the Transport Hygiene role.

## Example Usage

```terraform
# Query the DNS block lists, but never for the postmaster.
resource "msexchangeserver_ip_block_list_providers_config" "this" {
  enabled             = true
  bypassed_recipients = ["postmaster@contoso.com"]
}
```

## Schema

### Optional

- `bypassed_recipients` (Set of String) Recipients whose messages are never checked against the providers.
- `enabled` (Boolean) Whether the providers are queried.
- `external_mail_enabled` (Boolean) Query them for connections from outside the organization.
- `internal_mail_enabled` (Boolean) Query them for authenticated partners and internal servers.

### Read-Only

- `id` (String) Always `default`.

## Permissions

On an Edge Transport server, the account is a local administrator: Exchange has no role-based access control there. On a Mailbox server with the anti-spam agents installed, it needs the **Transport Hygiene** management role, which the role group created by [`tools/new_role_group.ps1`](https://github.com/workplace-as-code/terraform-provider-msexchangeserver/blob/main/tools/new_role_group.ps1) does not include. See the [Authentication guide](https://registry.terraform.io/providers/workplace-as-code/msexchangeserver/latest/docs/guides/authentication).
